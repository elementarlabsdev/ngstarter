Block format & import

Export structured content from another system directly into Content Editor’s native version-1 JSON document. This reference describes every built-in block, its saved fields and its HTML import mapping.

Document envelope and common fields

  • version must be 1. blocks is ordered and may be empty. Only these two document envelope fields are part of the format.
  • Every block requires a non-empty id, type and content. Block IDs are globally unique across the root, toggles and grid descendants.
  • attrs.settings stores block settings; attrs.props stores properties. Alignment uses {name: 'text-alignment', value: 'left' | 'center' | 'right' | 'justify'}.
  • All text fields use text runs with an explicit marks array. Empty text is an empty array or a single empty run. Newlines are literal text; HTML is never stored inside text runs.
  • JSON import retains extra JSON fields inside block content/attrs and preserves valid IDs. Duplicate IDs, malformed fields, unsafe resource URLs, cycles and non-JSON values produce a structured error.
  • Do not serialize component instances, signals, runtime upload callbacks, isEmpty or builder view/cell objects. The builder may normalize empty root documents, text runs and table rows for editing.

Color marks accept supported CSS color strings, including hexadecimal, named colors, rgb/hsl expressions and safe CSS variable references. Links allow web, email, telephone and relative URLs. Media allows appropriate web/relative/data/blob resources; iframe embeds allow web/relative URLs only. The importer performs these semantic checks in addition to JSON Schema validation.

Import API

  • contentEditorFromJson(source, config?, options?) accepts JSON text or a native object, validates the whole nested document, and returns a detached ContentEditorDocument.
  • contentEditorFromHtml(html, config?, options?) imports HTML text. Browser DOM is required; on the server supply a DOM document through options.document. It must support implementation.createHTMLDocument().
  • ContentEditorImporter.fromJson/fromHtml also reads the environment configuration and injected DOCUMENT. Standalone functions use only the explicitly supplied config.
  • builder.importJson/importHtml use the same source/config/options arguments. They replace the initialized builder’s document by default, or insert with mode: "insert" and a target. Both are one undoable edit, clear stale block selection and emit contentChanged. They return the live document after normalization. Failed import does not alter content, history, selection or drafts.
  • Options default to maxDepth: 64, maxBlocks: 10000, allowUnknownBlocks: false. Limits must be positive integers and include descendants. The JSON Schema describes built-ins; use explicit custom config or allowUnknownBlocks to transport custom types.
  • Errors expose ContentEditorImportError.path and message, pointing at the first invalid field, for example $.blocks[2].content.cells[0].blocks[1].id.

HTML fidelity

Semantic blocks, supported marks, alignment, lists, table metadata, callouts, details and exported gallery/grid structures are converted into native blocks. Scripts, style sheets, executable resources, event handlers and arbitrary HTML/CSS are not stored. Unsafe links keep their visible text. Unsupported wrappers keep supported text/descendants; unsupported or unsafe media is omitted.

HTML cannot recover original IDs, upload metadata, custom attrs, video orientation, or attachment size/MIME. It generates fresh IDs and defaults. Mixed nested list styles map to the parent list type. Use native JSON for lossless transfer. No legacy-format migration is performed.

Unified custom blocks

Register an editor, preview renderer, initial native content, menu item, validation and HTML import/export in a single block entry. Use loadEditor instead of editor for lazy components. Nested Grid/Toggle previews inherit the instance configuration. The editor demo includes a Bookmark block using this API.

Drafts and media uploads

Drafts save after a delay, validate before restoration and expose saving/error status. Set a stable, distinct documentId for each document. Media shares cancellation, progress, visible errors and retry; carousel retry sends only failed files.

Custom import configuration

Use provideContentEditorConfig in application or route environment providers. Child environments inherit parent defaults. Import priority is built-ins, environment config, builder instance config, then per-call config.

A block’s fromHtml has a CSS selector and parse(element, ctx). Overrides run before built-ins and may return one block, multiple blocks, or null. Context provides createBlock, createId, parseText, parseBlocks, safeUrl and defaultFromHtml. The latter calls the built-in parser without recursively invoking your override; nested parseBlocks calls keep configured handlers.

validateImport(block) returns undefined to accept or a message to reject the block. Built-in validation still runs first. Configure importMarks with extra Headless Editor mark definitions for HTML parsing; HTML export mark converters use config.marks. Custom callbacks are application-owned.

Import configuration alone does not create an editable block component. Custom types/marks need matching application renderer components or Headless Editor plugins. Refer to the renderer API for custom read-only block rendering.

Third-party exporter checklist

  1. Emit UTF-8 JSON with version: 1 and globally unique block IDs.
  2. Use text runs with explicit marks, nested list children, toggle blocks and ordered grid cells.
  3. Put table text in attrs.rows, metadata in attrs.cellMetadata, and settings/properties inside attrs.
  4. Include required media fields and byte counts/MIME; use persistent URLs for production assets. Runtime uploadFn callbacks are not saved data.
  5. Validate against the downloadable schema and call contentEditorFromJson for semantic checks before storing/importing.
  6. Use JSON for exact round trips and HTML for interoperable display/conversion.
